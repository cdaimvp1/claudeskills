## Overview tab (competitive-RFx variant, pv-06-overview.js)

No sub-tabs. One long scroll, top to bottom:
1. Round banner (conditional) - shown only when a down-selection round is active.
2. RFx Summary - one narrative paragraph (plain-English scope, bidders, CCI classification).
3. Two-column band:
   - LEFT card "Key facts": 2-col label/value grid (RFx name, Stage, Owner, Next step, Sourcing rep, Estimated TCO, Health, CCI classification with a color swatch). Values never wrap; long values get a title tooltip.
   - RIGHT card "Participants": scalable roster (initials avatars, per-person Outlook-email / Teams-call icon buttons) plus a group contact picker popover (select a subset or all, one draft action). Owner and Sourcing rep pinned to the top of the two columns.
4. "Supplier participation & scoring" - the centerpiece table. Grouped header row (Participation columns vs Scoring columns /5 and coverage %), glyph flags (check-circle / half-circle / flag / dash) each with a hover tooltip explaining the state, per-column max-value cell emphasis, an advisory-leader ring on the lead supplier, elimination/continuing badges tied to round state, an "Email all (BCC)" action in the header.
5. "Where we are & what's next" - a vertical numbered stepper (8 stages, done/now states) beside a body with four blocks: "Your next action", "Happening now", "Next for the project", and a "Waiting on" roster with a reflect-only Nudge (draft reminder) button per outstanding person.
6. Two-week calendar - a 7-col x 2-week (or 5-col business-week) grid. Status-colored chips (done / active-now / upcoming / needs-you-specifically), weekends greyed, today ringed, 3+ items per day collapse to "+N more", every chip hovers open to a rich card (lead sentence, When/Due-by with time and duration, Owner, Sent-via system, Action).

Why it reads coherent:
- Single narrative-to-detail hierarchy: paragraph -> facts -> people -> the actual work (participation) -> status and next steps -> calendar. Every section answers one question in the natural order a person would ask it.
- Density is controlled: facts are compact 2-col pairs, not oversized tiles; the one genuinely dense object (the participation table) gets its own bordered card and legend so density is contained, not spread everywhere.
- Color is functional only: CCI swatch, a 3-state health pill (on-track / at-risk / breached), and 4 flag glyphs are the ONLY non-neutral colors on the page. No decorative color anywhere.
- Progressive disclosure via hover, not a legend wall: every table header and every calendar chip carries a data-tip/hover card instead of a separate help tab.
- One interaction contract site-wide: every actionable control (Nudge, per-person email/call, group picker) is a reflect-only draft-and-confirm action, never a live send. A user learns this once and it holds everywhere.

## Documents tab (pv-14-docs-comms.js: docsHTML)

1. Optional "Live document index" band (only when a real platform record is loaded) - reflect-only rows, each with a retention pill, a version-count chip (opens a read-only version-history drawer), an Open link, and a footer note that Microsoft Purview stays the enforcer.
2. Toolbar: search box, a Tree / List view toggle, an Add Folder button.
3. Tree view: recursive collapsible folders (drag-and-drop file moves trigger a misfile-detection confirm dialog naming the recommended folder; a "+ Subfolder" affordance on every folder; a "SoR" badge on the Risk & Deviation Approvals folder) beside a right-hand split detail pane (metadata key/value grid plus a clearly captioned "Summary - generated by Theo" one-line description, reflect-only, not written back to the document).
4. List view: one flat sortable/filterable table, 10 columns (Document, Type, Executed, Expires, Annual $, TCO, Business owner, Sourcing rep, Home, Status); click a header to sort (arrow indicator); inline "reassign owner" action; the Home column visually distinguishes SharePoint (editable now) vs LEAH source (read-only reference, executed contracts) vs SoR archive (final/complete).
5. Footer note: plain-language SharePoint-vs-LEAH-vs-system-of-record explainer plus an "Archive final copies to the SoR" action.

Why it reads coherent: one toolbar drives two equivalent projections (tree vs flat list) of the exact same file set, so switching views never loses the user's place; every automated judgment (misfiled, retention class, one-line summary) is captioned as Theo-generated/draft and gated behind a human confirm click; color is reserved for meaning (status pill, SoR badge, home-location chip) against an otherwise plain-text list.

## Comms tab (assets/pv/pv-comms-signalmap.js: cmTabHTML, the "signal map")

Sub-tabs for 4 views: River Convergence / Phase Alignment / Convergence Network / Topic Flow. Each view opens with an "Explain" card (name + one paragraph + a bolded "Best for X" line), then a shared scope lens (All / per-supplier / All bidders / Internal, colored pill buttons), then the active SVG visualization in a bordered card with its own legend and a zoom control, then a "Communications Review Queue" (collapsible; items Theo held back as personal/borderline, a human must Add or Skip, nothing auto-enters the shared record), then a unified filter bar (free-text search + Topic / Channel / Person / Status selects) whose live "N of M communications match" count drives BOTH the chart above and the flat list below, then a click-to-open detail panel (quote, Clarity/Confidence/Alignment metric bars, an "Open in Outlook/Teams" deep link when the viewer was a participant else a polite gating note, up to 6 related communications), then the full communications list, newest first.

Why it reads coherent:
- One state object (view, scope, topic, channel, person, status, q, sel) drives every visible surface at once, so a filter change updates the chart, the match count, the list, and clears any stale detail panel together.
- Every one of the 4 views shares the same "click a dot or node -> the same kind of detail card opens" contract, so the interaction is learned once and reused four times.
- Disciplined visual grammar reused across all 4 views: 3 fixed channel colors (email/chat/call), 4 fixed status border-styles (solid green Agreed / dashed mustard Open / solid red Disputed / dotted mustard Flagged), and CSS-custom-property per-supplier dot colors that also carry the light/dark theme.
- The Review Queue is a governance device, not just content: it visually separates "Theo already decided this belongs in the shared record" (the 4 views + list) from "a human must decide" (the queue), which is what keeps the shared record trustworthy without hiding anything.
- Reflect-only is stated in the tab's own intro copy and reinforced again at the point of use (the gating note on a thread you were not a participant on), not buried in a separate policy page.

## lilly-contract-review v3.2 (deepest overlap: it has its own Documents sub-tab)

Structure: 3 panels (Contract Review / Legal Negotiation / Commercial Analysis), each with fixed sub-tabs. Panel 1 ("Contract Review") has 7: Overview, Risk Heatmap, Findings, Protection & Coverage, Obligations, Vendor Tactics, Documents.

Documents sub-tab: KPI row (Documents in Family / Executed-Filed count / Draft-Under Review count / Evidence Awaiting count) + a Document Register (List / Folder-Tree toggle over the SAME 7-column table: Document, Type, Status, Date, Value, Owner, Retention) with a paired narrative callout, + a Compliance Evidence Checklist (7 fixed required-evidence items, each Filed/Draft/Pending/Awaiting, each naming the sign-off gate it blocks) with its own paired callout.

Overview sub-tab: KPI row, a semicircular Protection Score gauge (4 fixed color bands: Critical/High/Moderate/Low) paired with a methodology narrative card, a Go/No-Go callout, a Governing Agreement Status card, numbered "Conditions Before Signature."

Visual language: dark #212121 header bar with a 4px Lilly-red left rule, Georgia serif for titles/large numbers, Arial for body/tables, left-border-accent "Card" and "Callout" boxes, rounded "Pill" status badges, dark-header STable rows.

WORTH RETAINING (the platform has no equivalent):
- The Compliance Evidence Checklist's "names the gate it blocks" framing (SCC/TIA -> Privacy Office sign-off, Data Escrow Memo -> Cyber ISS sign-off) is sharper and more decision-relevant than the platform's plain retention-pill/misfiled-flag: it turns "what's missing" into "what's blocked, and by what."
- Document-family framing: MSA + Exhibits + Addenda + WOs + evidence + invoices treated as ONE family with a rollup KPI row (Executed/Filed vs Draft/Under Review vs Evidence Awaiting) is a better at-a-glance single-deal health read than the platform's flat cross-project register, which has no rollup at all.
- The Protection Score gauge plus an explicit, auditable methodology paragraph (starting value 100, number of Covered categories, Hard Stop count, deduction basis) is a stronger "why is the number X" transparency pattern than the platform's Overview health pill, which asserts On track / At risk / Breached with no visible basis.
- Deterministic retention-class lookup (doc-type -> CONTRACT-ACTIVE / SOURCING-RECORD / COMPLIANCE-EVIDENCE / WORKING) always paired with a "draft, confirm with records SME" tag is conceptually close to the platform's retpill but scoped cleanly to one document family instead of a whole library.
- "Tracked Dates & Deadlines" strip (urgency-colored chips, soonest-first) and a By Party / By Date obligation sort toggle: the platform's Documents tab has no deadline-forward view at all today (Expires is just a table column, never surfaced as an urgency strip).

WEAK / incoherent vs the platform:
- Generic corporate visual language (dark-slate header, Georgia+Arial, a blue/amber/red pill palette) carries no Lilly-brand identity, no Theo/dino presence, no off-white warmth; it reads like a stock enterprise SaaS report, not "this app."
- Interaction model is static: tab/sub-tab clicks and a single List/Tree toggle. No search, no click-to-filter, no hover-for-detail, no drag-drop, no zoom, no linked filtering between the register and the checklist.
- The Document Register and the Compliance Evidence Checklist are two separate tables with two separate callouts sitting side by side; there is no visible link showing WHICH register row satisfies WHICH checklist row.
- No document-level detail drawer; clicking a row does nothing (contrast the platform's split detail pane, one-line Theo summary, and version-history drawer).
- Document Type is plain text, no per-type glyph (contrast the platform's fic icon on every file row).
- Single-contract scope only: no cross-project register, no live-vs-demo document index distinction, and critically no LEAH-vs-SharePoint-vs-system-of-record "home" concept - the platform's explicit separation of "documents you can act on" from "read-only executed source in LEAH" is an important trust boundary this skill's Documents sub-tab does not model at all.

## executive-summary-package (a DOCX/MD generator, not an interactive dashboard)

Worth retaining: the "Source Documents Line" (one line directly under the title, naming exactly which document(s) the summary was built from, with role and date when there are several) and the "Data Basis & Confirmations" footer (a single closing line: N of M fields extracted verbatim / N user-confirmed / N inferred and flagged [CONFIRM]). This is a strong, portable provenance convention - the written-document analog of the platform's reflect-only captions - and could anchor the foot of any dashboard panel that blends extracted fact with LLM-inferred content.

Weak/incoherent vs platform: it is a Word-document artifact with no screen, no navigation, no color system, and no chart to evaluate; its only contribution to this AREA is the trust-footer convention above, not a layout to imitate.

## theos-field-guide / Personal Command Center (PCC) v2.5, Comms lane (field-guide-engine.html: renderComms)

Structure: one combined "Comms convergence" panel = a compact river SVG (fixed topic lanes over a date axis, smoothed paths per topic, status-ringed nodes: Agreed blue / Open neutral-grey / Disputed amber / Flagged red) directly above a "Topic flow" heat row (per-topic day-intensity cells 0-3 plus a stalled/active tempo tag). Clicking a node opens an inline detail (status chip, date, one-line label, one-line citation, a Clear button). Shows an explicit empty state when no comms data is supplied for the run.

Weaker than the platform: it is ONE always-on view, not four - no Phase Alignment (contradiction detection), no Convergence Network (citation graph), no filter bar (no Topic/Channel/Person/Status/search), no scope lens (no per-supplier isolation), no review queue (no held-back personal/borderline gating), no "Open in Outlook/Teams" deep link, no Clarity/Confidence/Alignment metrics on the detail card, and no per-supplier dot color (only status-ring color). Channel (email vs chat vs call) is not encoded anywhere, whereas on the platform channel color is load-bearing across all four views.

Worth retaining:
- The single-glance MERGE of river + tempo into one panel (no sub-tab hunting) genuinely suits a personal daily-check tool better than a four-tab explorer would - PCC is "check this each morning," not "investigate this deal," so collapsing to one combined view is the right call for that context, not a deficiency to fix by copying all four platform views wholesale.
- The `#fgData` JSON-island data contract with defensive parsing (try/catch, non-blocking banner on a malformed payload, merge-by-id upsert rather than full overwrite) is a materially more robust data-injection pattern than the platform's demo-data model and is worth carrying INTO the platform-inspired build as a resilience pattern, not just inheriting from it.
- The abstaining next-best-action pattern on the Issues lane (a confidence pill; a grounded abstention with a stated reason and what-would-resolve-it, instead of a fabricated recommendation when signal is weak) is a real anti-fabrication device the platform's Comms tab has no equivalent of: every synthesis node on the platform is presented with equal authority regardless of how thin its evidence is.

3. NEWEST VERSION (the proposal)
=================================================================

Overall approach: keep the platform's three tab skeletons almost entirely intact (they are already the stronger artifacts in every 1:1 comparison), and graft in the specific skill-side ideas that add real value without disturbing what already works. Do not introduce Georgia serif, left-border cards, or a new icon set; extend the existing Libre Franklin / top-accent-border / hairline-card / hover-tooltip system already in place.

## A. Overview tab (merged) - light-touch changes only

1. Round banner - unchanged.
2. RFx Summary narrative - unchanged, PLUS a small right-aligned caption line under the paragraph in the existing muted-caption style: "Grounded in: RFP document, 3 supplier responses, 14 internal messages" (borrows executive-summary-package's Source Documents Line convention as a one-line provenance caption, not a new section).
3. Key facts + Participants band - unchanged, EXCEPT the Health pill (On track / At risk / Breached) becomes hoverable: a small data-tip card explains the basis in 1-2 sentences, e.g. "At risk: 2 of 4 review gates (Cyber, TPRM) still open against 9 business days of runway (historical median 11 days)." This borrows lilly-contract-review's "auditable methodology" discipline (the Protection Score's "why is the number X" card) applied to the existing health pill, using the platform's existing hover-tooltip idiom (data-tip), not a new card.
4. Supplier participation & scoring - unchanged (already the strongest artifact here; no changes needed).
5. Where we are & what's next - unchanged, EXCEPT the "Your next action" line gains an abstain state: when Theo's confidence in the recommended action is low, render a plain "Needs more signal: [reason]" line (muted, no icon-of-false-certainty) instead of always asserting an action. Borrowed from PCC's abstaining next-best-action pattern.
6. Two-week calendar - unchanged.
7. NEW, optional, collapsed-by-default footer strip: "Documents & comms at a glance" - 3 small tiles reusing the platform's existing KPI-tile visual component:
   - "Documents" - Executed/Filed vs Draft/Awaiting count, links to the Documents tab
   - "Communications" - settled vs open vs disputed thread count (read from the Comms tab's own node-status computation, so all three surfaces agree), links to the Comms tab
   - "Tracked deadlines" - the single soonest urgency chip (reusing the calendar's chip visual), links into the Documents tab's new deadlines strip (see B below)
   This is the one net-new idea for Overview: pull contract-review's family-health-KPI-row concept and PCC's KPI-strip concept UP into Overview as a cross-tab index, so landing on Overview immediately signals whether Documents or Comms need attention, without tabbing over blind.

New outline, top to bottom:
1. Live document index band (unchanged)
2. NEW KPI strip (reuses the platform's existing KPI-tile component, sized to match tiles used elsewhere in the app, NOT contract-review's larger 28px Georgia numerals): [Documents in family] [Executed / Filed] [Draft / Under review] [Evidence awaiting]. Computed over the current folder scope by default; "project-wide" is a one-click toggle.
3. Toolbar: search box, a 3-way Tree / List / Evidence toggle (was 2-way Tree/List), Add Folder button
4. Tree view - unchanged
5. List view - unchanged 10-column table, PLUS a NEW "Tracked deadlines" strip inserted directly above the table: horizontally scrollable urgency-colored chips (reusing the two-week-calendar's chip visual language and hover-card idiom), one per document with an Expires date, soonest-first; clicking a chip opens that document's existing detail pane.
6. NEW Evidence view (the 3rd toggle state): the fixed required-evidence checklist (W-9, SOC 2 Type II, ISS Security Questionnaire, cross-border SCC/TIA, Data Residency Screen, Risk Acceptance Memo, Policy-Deviation Approval) cross-referenced against the SAME Document Register rows already shown in List view (not a separate dataset) - each row: item, status pill (Filed / Draft / Pending / Awaiting, using the platform's existing status-pill colors), the gate it blocks, and (when Filed) a direct link/reference to the register row that backs it, honoring the same "never mark Filed without a matching document on record" rule from the skill. Net effect: the register (List), the folder view (Tree), and the compliance read (Evidence) are three projections of ONE underlying file set and one KPI strip, matching the platform's existing "one toolbar drives multiple equivalent projections" pattern from section 1, rather than the skill's current pattern of two disconnected tables.

## C. Comms tab (merged) - add a compact default view and an evidence-confidence signal; keep everything else

Keep exactly as built (per Marc's framing that the platform already wins the 1:1 comparisons): the scope lens, the unified filter bar (search + Topic/Channel/Person/Status), the Review Queue, the detail panel (quote, Clarity/Confidence/Alignment metrics, Open-in-Outlook/Teams deep link), and all 4 existing views (River Convergence, Phase Alignment, Convergence Network, Topic Flow) with their current visual grammar untouched.

New sub-tab order (left to right):
1. NEW "At a glance" (becomes the default landing sub-tab) - PCC's merged river+tempo single panel, compact, no filter bar, no zoom control: one screenful answering "how is this going" instantly. Ends with a plain link, "See the full signal map ->", which drops the user into the existing 4-view explorer below at whichever view they last used.
2. River Convergence - unchanged.
3. Phase Alignment - unchanged SVG waves, PLUS: when a Disputed "OUT OF PHASE" node is clicked, the existing detail panel gains one additional block, a plain-language dual-quote diff ("Written, Jun 13: [quote]" stacked over "Said on the call, Jul 1: [quote]"), directly satisfying the skill-recon finding that the sine-wave encoding alone is hard to parse, without removing the wave visualization itself.
4. Convergence Network - unchanged, PLUS: any synthesis node backed by exactly 1 message gets a thin-evidence tag next to its receipt count in the detail panel ("Low confidence: only 1 message behind this"), borrowed from PCC's abstain discipline. No visual change to the node itself (radius-by-evidence-count already communicates this implicitly); this only makes it explicit in the panel copy.
5. Topic Flow - unchanged.

Net-new cross-tab wiring: the Overview tab's new "Communications" tile (section A.7) and the "At a glance" sub-view here both read from the SAME node-status computation (settled/open/disputed counts), so Overview, the Comms landing view, and (in a future Total Recall bridge) PCC never show three different answers to "is this settled."

4. DESIGN NOTES
=================================================================

- Palette: warm off-white app background #FBFAF9 (--bg), near-black ink #1A1A1A (--ink), hairline #E7E4DF (--line), white surface cards. Dark mode is an ADDITIVE token layer (html[data-theme="dark"] overrides), never a separate redesign - any new KPI strip, Evidence view, or "At a glance" panel must ship both light and dark values the same way the Comms signal map already does (LIGHT_VARS / DARK_VARS pattern in pv-comms-signalmap.js).
- Wordmarks: a black Lilly wordmark plus a "Theo" wordmark set in Sacramento (script), per assets/theo-brand.js. If PCC is ever pulled toward this visual system, its header ("Personal Command Center" in Ringside / ITC Garamond Narrow LDS fonts, with a literal emoji-scale dino) should swap to the same asset-based theo-dino-mark.png plus the Sacramento wordmark plus Libre Franklin body text, not keep its separate LDS type system.
- Dino mascot: assets/theo-dino-mark.png, parked to the right of the wordmark, with existing idle/sleep animation states. Use it as a small ambient header/footer presence only, never as decoration inside a data panel (Evidence view, KPI strip, deadline chips all stay dino-free).
- Typography: Libre Franklin for everything (the FONT variable already used across pv-comms-signalmap.js and the rest of the platform). Do NOT bring in lilly-contract-review's Georgia-serif-for-titles convention when porting its Documents/Evidence ideas across; render new titles at the same weight/size scale already used for .comms-head / .secthd / .glabhd.
- Card and panel styling: 1px hairline border, 10-11px border-radius, a thin (3px) colored TOP-accent border used for meaning (e.g. plum on comms detail panels), matching .theo-comms .detail and .explain. Do not adopt contract-review's 4px LEFT-border Card/Callout convention when building the new Evidence view or KPI strip; keep the top-accent-border idiom for consistency.
- Color-as-signal discipline: color is reserved for status/meaning only (health pill, flag glyphs, retention pill, channel color, status-ring color, per-supplier dot color) and the site-wide 3-colour rule already locked elsewhere in the product applies here too. Lilly has no on-brand green, so new status pills in the Evidence view and KPI strip should reuse the SAME existing plum/teal/mustard/red/blue vocabulary already defined in the platform's CSS custom properties, not contract-review's separate POS/AMB/GOLD/R token set.
- Density and spacing: the platform's compact 2-col label/value "fact" grid (10px uppercase 700-weight label over a 12.5px value) and 13-13.5px table/row text should size the new KPI tiles and Evidence rows, not contract-review's larger 28px Georgia "Metric" numerals - so a new "Documents in family" tile sits comfortably beside existing tiles elsewhere in the app.
- Iconography: inline stroke-based SVG line icons at 14-18px (the existing mail envelope, phone/call, folder, search-magnifier glyphs already in pv-06-overview.js and pv-14-docs-comms.js). Reuse these exact icon shapes for any new Evidence/Deadlines affordances rather than introducing a new icon set.
- Motion and interaction: the two standing idioms are hover-reveals-detail (data-tip tooltips, calendar-chip hover cards) and click-opens-detail-panel (comms nodes/dots, document rows). Every new surface proposed above (the Overview health-pill tooltip, the Documents deadlines strip, the Evidence view rows, the Comms confidence tag) should reuse one of these two idioms rather than introducing a third pattern such as a new modal dialog for a simple info reveal.
