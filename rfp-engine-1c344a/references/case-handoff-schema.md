# Case Handoff Schema - rfp-engine → rfp-case-manager

Schema for `case_handoff.json`. This payload is generated by rfp-engine when user selects case handoff. rfp-case-manager consumes it to initialize or update the case file. If a Microsoft Team is bound, it maps artifacts to the existing Teams/SharePoint structure. It does not create SharePoint folders, provision Teams channels, move files, send notifications, or return a live case URL.

---

---

## Validation Rules

rfp-case-manager must validate on receipt:

| Check | Rule |
|-------|------|
| `schema_version` | Must be "1.0" |
| `case.case_id` | Must be unique - reject duplicates |
| `artifacts.files` | All paths must be resolvable |
| `schedule.proposals_due` | Must be after `schedule.qa_deadline` |
| `suppliers` | At least 1 supplier with status "Invited" |
| `stakeholders` | At least 1 with `approval_authority = true` |

---

## rfp-case-manager Actions on Receipt

1. Validate the handoff payload.
2. Create or update the local case file.
3. Map artifact paths to the case file.
4. If a Team is bound, summarize the existing SharePoint/Teams structure and recommend where artifacts belong.
5. Generate scheduling/status draft text for the user to execute manually.
6. Confirm case initialization to the user.
